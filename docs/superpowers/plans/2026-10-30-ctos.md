# ctOS Implementation Plan

> Execute inline using superpowers:executing-plans; test security behaviors before implementation.

**Goal:** Gate catalogue reading by pickup and add a ctOS account console.
**Architecture:** Request-scoped fresh Neon sessions; uncached SQL authorization; server-only account operations and small client forms.
**Tech Stack:** Existing Next, React, Zod, Neon Auth/Postgres.
**Spec:** ../specs/2026-10-30-ctos-design.md

## Constraints and review focus
No new providers or dependencies. Do not expose session tokens, grant admin reading bypass, cache per-user grants, or imply downloaded files are revocable. Verify wrong-book/member, returned loans, forged session IDs, upstream errors, and mobile controls.

- [ ] Add failing disposable-Postgres tests for `canReadCatalogBook(userId, bookId)` in `src/lib/queries/reading.js`; implement exact ownership, picked-up timestamps, nonreturned and nondeleted book predicate.
- [ ] Add shared catalogue authorization to `sources.js`, locked contents in `edition-pages.js`, and conditional entry controls on book detail; retire restricted export with private/no-store response. Verify direct routes and anonymous requests.
- [ ] Add failing service tests for `src/lib/account/service.mjs`: validated profile/password operations, sanitized session model, own-session membership checks, errors and revocation. Implement wrappers with fresh Neon session in `src/app/account/actions.js`.
- [ ] Add `src/app/account/page.js` and account forms, current-device state, browser-history clearing and ctOS branding. Apply defensive headers and fresh session DAL. Test forms/empty/error states and responsive layout.
- [ ] Run unit and DB suites, lint, production build and browser checks. Review security boundaries, document residual provider/deployment limitations, then commit and push main under existing authorization.
